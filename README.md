Здравствуйте! Расскажу про проект, который я сделал для SK Kids Challenge.

Бот — не справочник с ответами. Он работает как наставник: задаёт неудобные вопросы, принимает ответ текстом или голосом, сравнивает его с реальными ситуациями из открытых источников и разбирает по полочкам — что получилось хорошо, что стоит поправить и как такой ответ звучал бы у человека, который уже прошёл этот путь.

---

## Проблема

Выбрать вуз или первую работу в 16 лет — сложно. Требования на сайтах вузов написаны канцелярским языком, отзывы противоречат друг другу, а критерии, по которым тебя правда возьмут на стажировку, нигде не опубликованы.

Наставник, который объяснил бы это живым языком, есть не у каждого. Бот — попытка заменить его на первых шагах.

---

## Что сделано

**База знаний.** 76 файлов: три сценария в меню (вуз, работа, первый месяц в компании) плюс отдельная база по лидерству. У 70 файлов в метаданных есть прямая ссылка на источник — официальные сайты вузов и компаний, hh.ru, habr, vc.ru, РИА Новости; ещё 6 кейсов авторские, источники в них перечислены без конкретного URL. Всё лежит в папке `data/`, и бот подмешивает нужное в ответы.

**Инфо-режим.** Выбираешь сценарий и спрашиваешь что угодно — бот ищет ответ в базе знаний и отвечает своими словами, а не копирует статью. Поиск сделан на TF-IDF с упрощённым стеммингом, так что находятся не только точные совпадения, но и похожие формулировки. Поиск ограничен разделами выбранного сценария, поэтому при вопросе про вуз бот не подтянет статью про лидерство. Под ответом — блок «📚 Источники»: название материала и ссылка на сайт, без путей к файлам на диске.

**Экзаменатор.** Бот выдаёт 3, 5 или 10 заданий по сценарию. Каждое второе задание — тест с четырьмя вариантами ответа, остальные — открытый вопрос. Варианты идут списком под вопросом, а кнопки в чате — просто буквы A, B, C, D. Если модель вместо ответов прислала буквы-заглушки или спрятала варианты внутри текста вопроса, бот достаёт настоящие варианты оттуда, а совсем битый тест заменяет открытым вопросом. Ответить можно текстом или голосом. После ответа выбранный и верный варианты помечаются прямо в задании, повторный ответ на то же задание не засчитывается дважды. При переходе к следующему заданию предыдущее и его разбор убираются из чата, чтобы не засорять переписку. Последнее задание разбирается так же, но итог открывается кнопкой «🏁 Завершить». Каждый ответ разбирается по одной схеме: оценка от 0 до 10, что сделано верно, что улучшить, пример хорошего ответа из практики, ссылка на источник. Итоговый отчёт остаётся в чате: из него можно вернуться в меню, а PDF выгрузить в любой момент.

**Типовые ошибки.** Отдельный список фраз, которые слышишь от абитуриентов чаще всего: «я ничего не умею», «опыта нет», «портфолио не успел собрать». Бот ловит их прямо в ответе и мягко подсвечивает, подсказывая, как лучше сформулировать.

**Память об ошибках.** Бот записывает, на каких заданиях и сколько баллов набрал. Слабым считается кейс, где попыток больше одной, а средний балл ниже 7. В следующих сессиях первое задание подбирается именно под слабое место, а в конце задаётся уточняющий вопрос по самой проваленной теме.

**Отчёт в PDF.** По команде `/export` или кнопкой в чате можно выгрузить результаты: текст каждого задания, твой ответ, балл, рекомендации по слабым темам, список источников (реальные ссылки из тех материалов, что использовались). Файл приходит прямо в чат.

**Голос.** Голосовое сообщение бот принимает всегда и распознаёт на русском или английском (по языку интерфейса). Озвучивает ответ нейронным голосом Microsoft только тогда, когда в настройках включён «Голос», — по умолчанию отвечает текстом.

**Индикатор загрузки.** Пока бот подбирает задания, в чате показывается стикер-индикатор, а после генерации он удаляется. Если пак стикеров не настроен, вместо него уходит короткий текст.

## Архитектура и стек

```
bot/
├── core/           # AI-движок, поиск по базе, адаптивность
│   ├── ai_engine.py        # GigaChat: генерация заданий и оценка ответов
│   ├── choice_options.py   # разбор вариантов ответа, защита от буквенных заглушек
│   ├── rag.py              # поиск по базе знаний
│   ├── adaptive.py         # память ошибок и слабые места
│   ├── prompt_registry.py  # промпты в yaml с версиями
│   └── common_mistakes.py  # список типовых ошибок
├── handlers/       # хендлеры Telegram
│   ├── start.py        # меню, настройки, /export
│   ├── info.py         # инфо-режим
│   ├── examiner.py     # экзаменатор
│   ├── voice.py        # голосовые сообщения
│   ├── pdf_export.py   # выгрузка отчёта
│   └── inline.py       # поиск по базе прямо из чата
├── utils/          # клавиатуры, голос, pdf, переводчик, индикатор загрузки, падежи
├── database/       # SQLite
└── prompts/        # реестр промптов
```

- Бот — aiogram 3.x: роутеры, FSM, reply и inline клавиатуры
- Модель — GigaChat (Сбер)
- Поиск по базе — TF-IDF плюс упрощённый стемминг для русского
- База — SQLite через aiosqlite (схема v5: в ответах кейсов хранятся текст задания и источники)
- Распознавание речи — SpeechRecognition, сервис Google (mono 16 кГц, ru-RU/en-US)
- Синтез речи — edge-tts, нейронные голоса Microsoft для ru-RU
- PDF — fpdf2, шрифт DejaVu
- Промпты — реестр в yaml с версиями, чтобы можно было откатить формулировки
- Тесты — 393 автотеста на pytest (все проходят), ruff без замечаний

## Как это работает

Внутри всё выглядит так: пользователь пишет или говорит → текст чистится от лишних символов и подозрительных инструкций → по базе знаний ищутся подходящие куски → вместе с промптом сценария они уходят в GigaChat → ответ показывается с указанием источников. В режиме экзаменатора добавляется оценка ответа и разбор по слабым местам.

Чтобы посмотреть, как это выглядит со стороны пользователя, достаточно пройти пять шагов: `/start` → выбрать сценарий → задать вопрос в инфо-режиме → пройти три задания в экзаменаторе, ответив текстом или голосом → нажать кнопку выгрузки отчёта.

## Этика

Бот не просит телефон, адрес или другие личные данные — в ответе есть прямая просьба их не присылать. В базе остаётся только то, что Telegram сам отдаёт профилю: id, имя и username, без них нельзя вести переписку и помнить прогресс.

Все данные для базы знаний взяты из открытых источников, и источник указан рядом с информацией. В каждом разборе и в PDF-отчёте есть дисклеймер: рекомендации носят информационный характер и не заменяют официальные требования вузов и работодателей.

## Ограничения демо-хостинга

- Хостинг — бесплатный тариф Render. Он выбран как временное решение для показа: сервис может «засыпать» без внешнего HTTP-трафика и просыпается около минуты. Для полноценной работы 24/7 нужен платный тариф или свой сервер.
- Чтобы Render не засыпал, повесь бесплатный монитор UptimeRobot: HTTP-монитор на `https://<имя-сервиса>.onrender.com/health`, интервал 5 минут. Пока пинг идёт, сервис не уходит в сон.
- Переменные окружения в дашборде Render: `BOT_TOKEN`, `GIGACHAT_CREDENTIALS`, при желании `LOADING_STICKER_PACK` (короткое имя пака стикеров) и `LOADING_STICKER_EMOJI`. Без пака индикатор загрузки показывается текстом — бот работает как обычно.
- SQLite-база данных и файл памяти ошибок лежат в файловой системе контейнера, который пересоздаётся при редеплое — память диалогов и адаптивность на демо-хостинге обнуляются. Это ограничение free-тарифа, код хранит всё правильно.
- В дашборде Render (Settings → Build Command) должно стоять `pip install -r requirements.txt` — ту же команду хранит `render.yaml`. Скачивать ffmpeg отдельно не нужно: бинарник ставится вместе с pip-пакетом `imageio-ffmpeg`.

## Как запустить локально

```bash
git clone https://github.com/Kot3loy/Softline.git
cd Softline
python -m venv .venv
.venv\Scripts\activate          # Windows (Linux: source .venv/bin/activate)
pip install -r requirements.txt
# создать .env по образцу .env.example, заполнить BOT_TOKEN и GIGACHAT_CREDENTIALS
python main.py
```

Отдельно ставить ffmpeg не нужно: бинарник приходит вместе с pip-пакетом `imageio-ffmpeg` и используется для конвертации голосовых.

Запуск тестов: `.venv\Scripts\python.exe -m pytest tests/ -q`
